## 从属关系与学习范式

一句话：**AI 包含 ML，ML 包含 DL，DL 里现在最出名的是 LLM**。Agent 是用 LLM 搭的系统，不是模型；RAG 是给模型补资料的一种架构。

### 概念层级

**人工智能（AI）**　让机器具备感知、学习、推理、决策能力的技术总称；常见子领域有 CV、NLP、语音、机器人。易混点：不等于通用智能，多数系统只做一件窄任务。

**机器学习（ML）**　从数据里学规律，而不是人手动写规则。易混点：规则引擎、if-else 不算 ML。

**深度学习（DL）**　用多层神经网络自动学习表示。易混点：层数多不等于更强，数据和任务更关键。

**大语言模型（LLM）**　在海量文本上预训练、以预测下一个 token 为目标的模型。易混点：模型不是产品，ChatGPT 才是产品。

**多模态模型**　能同时处理文本、图像、音频、视频等模态。易混点：不是 LLM 的替代，通常是同一底座加不同模态。

**通用人工智能（AGI）**　能跨任务学习和迁移的 AI。易混点：没有统一定义和公认测试，别把某个榜单当证明。

### 学习范式

**监督学习**　用「输入—答案」成对的数据学映射。常见场景：分类、回归、目标检测。

**无监督学习**　没有标签，自己找结构。常见场景：聚类、异常检测。

**自监督学习**　从数据本身造训练目标。常见场景：预测下一个 token、掩码还原。

**半监督学习**　少量标注加大量未标注一起训。适用：标注贵、未标注数据多。

**迁移学习**　把一个任务上学到的表示或权重用到另一个任务；预训练加微调就是它的大规模应用。易混点：微调、LoRA 只是迁移的一种做法。

**强化学习**　靠试错和奖励学策略。常见场景：游戏、机器人、RLHF 与 RLVR。

**端到端学习**　从原始输入直接优化最终目标。常见场景：语音转写、自动驾驶感知。

**特征工程**　人工构造对任务有用的属性；传统 ML 的核心工作，深度学习把这步交给网络。

### 神经网络

**前馈网络**　单向逐层变换。常见用途：分类头、简单回归。

**CNN**　卷积核在图像上滑动、共享权重。常见用途：视觉、检测、端侧模型。

**RNN / LSTM**　用隐藏状态把历史带到下一步。常见用途：时序、传感器、部分语音场景。

**GAN**　生成器与判别器互相对抗。常见用途：图像生成，主流已是扩散模型。

**Transformer**　2017 年提出，用自注意力取代循环结构。常见用途：几乎所有大模型的底座。

**扩散模型**　先对数据逐步加噪，再训练网络从噪声还原；图像、视频生成的主流架构。

**过拟合与泛化**　训练集表现好、新数据差就是过拟合；更多数据、正则化、早停、验证集调参是常规解。真正要的是泛化。

## 大模型怎么工作

### 输入与表示

**Token（词元）**　模型处理的最小单位，可能是词、子词或标点；换个分词器 token 数就变，计费和上下文都按它算。

**分词器（Tokenizer）**　把文本切成 token 的规则，常见 BPE；主流分词器里一个汉字约 1–2 个 token，英文约 4 个字符 1 个 token。

**Embedding（嵌入）**　把 token、句子或图片映射成向量，语义近的距离近；不同模型的向量不能混用。

**位置编码（RoPE）**　用旋转给 token 编码相对位置；长上下文外推（NTK、YaRN 等）都从它改。

**上下文窗口（Context Window）**　一次请求能处理的 token 上限，输入和输出通常共用；「塞得进」不等于「用得好」。

**有效上下文**　模型实际能稳定利用的长度，通常小于标称窗口；长文中间最容易丢（Lost in the Middle）。

**上下文腐坏（Context Rot）**　上下文越长，模型对其中信息的利用越差；长上下文不是免费的。

**参数（Parameters）**　训练学到的权重和偏置；80 亿参数按 BF16 存约占 16 GB，训练还要算激活、梯度和优化器状态。推理显存粗算 = 参数量 × 字节数 + KV Cache。

### 结构与计算

Transformer 是底座，下面拆它的关键部件。

**自注意力（Self-Attention）**　每个位置按相关性汇集其他位置的信息；计算量随长度平方增长，所以长上下文贵。生成模型再叠因果掩码，让它只能看左边，避免「偷看答案」。

**多头注意力**　多组注意力并行学不同关系；GQA、MQA 让多个查询头共享少量 KV 头，省显存又提速。

**MLA（多头潜在注意力）**　DeepSeek 提出，把 KV 压到低维潜空间，长上下文更省显存。

**线性与稀疏注意力**　把平方复杂度压到近线性；2026 年常见「局部加全局」的混合注意力。

**混合专家（MoE）**　每个 token 只激活部分专家，用小激活换大容量；总参数和激活参数要分开看，工程难点在路由均衡和跨卡通信。

**激活参数**　每个 token 实际参与计算的参数，决定算力开销；显存和模型容量仍按总参数算。如 Qwen3.5-397B-A17B 是 397B 总参、17B 激活。

**BERT**　只用 Transformer 编码器、双向看上下文，擅长分类和抽取；和只能看左边的 GPT 类解码器相对。

### 训练目标与生成

**预训练（Pre-training）**　在海量无标注语料上做下一个 token 预测，得到基座模型；最烧钱的一步。

**基座模型（Base Model）**　只做完预训练、还没对齐的模型；会续写，但不一定会听指令。

**自回归（Autoregressive）**　一次生成一个 token，再接回输入继续生成；训练时整段并行算损失（teacher forcing），推理时只能逐个吐。

**Logits**　模型对词表里每个 token 的未归一化打分，经 softmax 变成概率；温度、top_p、top_k 都在这之后起作用。

**采样（Sampling）**　按概率挑下一个 token；温度、top_p、top_k 控制随机性，温度 0 是贪心，也不等于完全确定。

**Scaling Law**　损失随参数、数据、算力按幂律下降；用来判断该堆多大模型、喂多少数据。

**Chinchilla 最优**　给定算力，参数量和数据量要按比例涨（约 20 token/参数）；推理成本上来后，「小模型多数据」更流行。

**涌现能力**　规模到一定程度突然出现的能力；也有研究认为是指标造成的错觉，别当铁律。

**上下文学习（In-context Learning）**　不改参数，只靠当前输入里的示例或说明适应任务。

**零样本（Zero-shot）**　不给示例，只靠指令完成任务；比少样本省上下文，但格式和边界更难对齐。

**少样本提示（Few-shot Prompting）**　在提示中给几个输入和输出的示例，让模型照着示例处理新输入。

**思维链（CoT）**　让模型先写推理步骤再给答案；推理模型把这步藏进「思考 token」。

**推理模型（Reasoning Model）**　专门为多步推理训练、先想再答的模型；如 o 系列、DeepSeek-R1 和各家的 thinking 模式。

**测试时计算（Test-time Compute）**　推理阶段多花算力换准确率：更长思考、多次采样、搜索验证；不是所有任务都值得。

**推理强度（Reasoning Effort）**　厂商给的低、中、高档位，是行为信号而非严格 token 预算；思考 token 通常照常计费。

**幻觉（Hallucination）**　编造看似合理但无依据的内容；流畅、有引用格式都不等于有据。

**知识截止（Knowledge Cutoff）**　训练数据的时间边界；之后的事只能靠检索或工具补。

**灾难性遗忘**　在新数据上继续训练后旧能力退化；继续预训练要混旧数据，微调时只调少量参数也能缓解。

## 训练、对齐与压缩

**继续预训练（CPT）**　在通用预训练之后，用领域语料接着做下一 token 预测，补领域语言和知识；目标仍是预训练目标，要混入通用数据防遗忘。

**后训练（Post-training）**　预训练之后的所有加工：指令微调、偏好对齐、推理强化；决定模型好不好用。

**SFT（监督微调）**　用「指令加标准答案」教模型按格式回答；在指令数据上做时也叫指令微调，是最基础的后训练。

**RLHF**　人工给答案排序训奖励模型，再用强化学习优化；让模型更符合人类偏好，经典实现用 PPO。

**PPO**　近端策略优化：奖励模型打分、价值网络估优势，并限制每次策略更新的幅度；RLHF 的经典算法，比 DPO 难调。

**奖励黑客（Reward Hacking）**　模型找到奖励函数的漏洞，而不是真解决问题；RL 训练要专门防。

**DPO**　直接用偏好对训练策略，省掉奖励模型和 RL 流程；比 RLHF 简单稳定。

**GRPO**　组内相对比较的强化学习，不需要价值网络；DeepSeek-R1 用它训推理，成本低。

**RLVR**　用可验证的奖励（答案对错、测试是否通过）做强化学习；数学、代码、Agent 训练的主力。

**对齐（Alignment）**　让模型行为符合人类意图和价值观：有用、诚实、无害。

**Constitutional AI**　用一套原则让模型自我批评和修正，减少人工标注；Anthropic 提出。

**微调（Fine-tuning）**　在预训练模型上继续训练；适合学风格、格式、领域术语，不适合灌新知识；数据质量比数量更关键。

**LoRA / QLoRA**　冻结原权重只训低秩适配器，显存小、可多任务切换；QLoRA 再把基座量化到 4bit，单卡也能微调。

**PEFT**　参数高效微调的总称，LoRA、Adapter、Prefix Tuning 都算。

**合成数据（Synthetic Data）**　用模型生成训练数据；成本低，但要防错误累积和「模型自噬」。

**数据清洗与配比**　去重、去噪、按领域调比例；对效果的影响常比换模型更大。

**蒸馏（Distillation）**　用教师模型的输出（含软标签、推理过程）训学生模型；常见于压缩和便宜模型。

**量化（Quantization）**　用更低位宽存权重、激活或 KV Cache，如 FP8、INT8、INT4；省显存提速，但精度损失要看任务。

**混合精度**　训练时用 BF16 或 FP16 算、关键状态留 FP32；省显存又保稳定。

**反向传播**　用链式法则从损失回传梯度；深度学习能训练起来的基础机制。

**优化器（Optimizer）**　更新参数的算法；AdamW 是默认，Muon 在 Kimi K2 之后被多家大模型采用，收敛更快。

**分布式训练**　数据、张量、流水线并行把模型摊到多卡；FSDP、DeepSpeed、Megatron 是常见方案。

**MFU**　模型算力利用率 = 实际 FLOPs ÷ 硬件峰值，衡量训练集群跑得值不值；大厂常报这个数。

**Checkpoint**　训练中保存的权重快照；断点续训、回滚、评测都靠它。别和 Agent 的运行检查点混。

**PyTorch**　动态图的深度学习框架，训练和微调的默认选择；部署时有 ONNX 等路径。

## 推理、部署与成本

**推理（Inference）**　用训练好的模型做预测或生成；和训练相对。易混点：这里的「推理」是 inference，不是 reasoning（推理模型）。

**算力（FLOPs）**　一次前向约 2 × 激活参数 × token 数，训练约 6 × 激活参数 × token 数；估算成本先算这个，再乘硬件利用率和单价。

**Prefill / Decode**　推理两阶段：先并行算完输入，再逐个吐 token；前者吃算力，后者吃显存带宽。

**KV Cache**　缓存历史 token 的 Key 和 Value，避免重复计算；随并发和上下文长度线性增长，是长上下文显存占用的大头。

**PagedAttention**　像操作系统分页一样管理 KV Cache，减少碎片；vLLM 的核心优化。

**Continuous Batching**　请求随到随拼批，不用等整批跑完；提升吞吐的关键。

**投机解码（Speculative Decoding）**　小模型先草拟几个 token，大模型一次验证，按规则接受或拒绝；正确实现不改变输出分布，能提速。

**TTFT / TPOT**　首 token 延迟和每 token 延迟；前者决定「感觉快不快」，后者决定「读起来顺不顺」。

**吞吐（Throughput）**　单位时间处理的 token 或请求数；和延迟通常要取舍。

**vLLM / SGLang**　主流开源推理引擎，负责批处理、KV 管理和高吞吐。

**Ollama / llama.cpp**　本地跑量化模型，适合个人开发、端侧和隐私场景。

**端侧推理（On-device）**　在手机、PC 或 NPU 上跑小模型；延迟低、数据不出设备，但能力和上下文受限。

**提示词缓存（Prompt Caching）**　复用相同前缀的 KV，长系统提示和固定文档能明显省钱省时。

**缓存命中价**　命中缓存的输入 token 通常按更低价计费；长提示的成本要按命中率算。

**批处理 API（Batch API）**　非实时任务打包异步跑，通常有折扣；适合离线标注、批量总结。

**模型路由（Model Routing）**　按难度、成本、时延把请求分给不同模型；用小模型分流是最常见的降本手段。

**模型网关（LLM Gateway）**　统一多家模型的接口、密钥、限流和回退；换模型不用改业务代码。

**限流与重试**　429 和 5xx 要指数退避；写操作重试前先查结果，避免重复下单。

## 智能体与上下文工程

**智能体（Agent）**　能感知环境、调用工具、按结果调整行动的系统；核心是循环，不是聊天。

**智能体循环（Agent Loop）**　观察、决策、调工具、看结果、再决策，直到完成或触发停止条件。

**ReAct**　推理和行动交替的经典范式；今天的 function calling 循环是它的工程版。

**Plan-and-Execute**　先列计划再逐步执行；适合步骤多的任务，但要处理「计划过期」。

**反思（Reflection）**　让模型检查并修正自己的输出；能提分，也会陷入自我肯定。

**提示词（Prompt）**　给模型的输入，包含指令、示例和资料；用户消息和系统提示词是两种不同角色。

**提示词工程（Prompt Engineering）**　靠写提示、给例子提升效果；现在更多被当成上下文工程的一部分。

**系统提示词（System Prompt）**　规定本次模型调用遵循的角色和规则，跨轮沿用取决于应用如何管理会话。

**结构化输出（Structured Outputs）**　用 JSON Schema 约束字段和类型，程序好接；字段值仍要校验。

**工具调用（Function Calling）**　模型提出工具名和参数，由应用在模型之外核验权限与参数，再调用工具。

**工具路由（Tool Routing）**　在已知工具里挑下一步用哪个；工具描述和命名写不好，模型就会选错。

**工具搜索（Tool Search）**　工具多到几十上百个、定义塞不下时，先按关键词或语义检索，只把相关工具放进上下文；是否支持按需加载取决于客户端实现。

**工作流编排（Workflow）**　预先定义步骤、分支和失败处理，例如发票查重后按金额转给相应审批人。

**工作流 vs 智能体**　工作流按预设路径编排任务，智能体可根据中间结果自行选择后续步骤和工具。

**上下文工程（Context Engineering）**　决定每轮给模型哪些指令、历史、工具结果和资料；比写提示词更接近系统设计。

**上下文压缩（Compaction）**　上下文快满时把历史总结成摘要、保留近期原文；做不好会丢关键约束。

**按需取数（JIT Context）**　不预加载全部资料，让模型需要时再用工具查；省 token 也更准。

**记忆（Memory）**　跨轮或跨会话保留信息：短期（当前对话）、长期（持久存储）、工作记忆（任务状态）。

**子智能体（Subagent）**　主智能体把子任务交给独立上下文的下级，收回结论；隔离上下文、便于并行。

**多智能体（Multi-Agent）**　多个角色分工协作；常见形态是编排者拆任务、工作者执行、审查者把关，协调成本随数量上升。

**计算机使用（Computer Use）**　模型看屏幕、点鼠标、敲键盘操作软件；慢且脆，适合没有 API 的系统。

**浏览器智能体（Browser Agent）**　用浏览器查资料、填表、下单；要防注入、防误操作、加人工确认。

**编程智能体（Coding Agent）**　能读代码、改文件、跑测试；交付看 diff 和测试，不看它说「完成了」。

**Vibe Coding**　用自然语言描述、主要靠运行效果迭代，少看代码；适合原型和一次性工具。

**Agentic Engineering**　人定目标、约束和验收，Agent 实现并验证；交付责任仍在人。

**Harness**　模型之外的运行环境：工具、上下文、权限、状态、反馈和停止条件；同一模型换 harness 效果差很多。

**循环工程（Loop Engineering）**　2026 年的新说法：把 Agent 的「计划—执行—验证—停止」当成工程对象设计，而不只是调提示词。

**SDD（规格驱动开发）**　先写清行为、边界和验收，再让 Agent 实现；规格进 Git，可评审、可回归。

**人在回路（Human-in-the-loop，HITL）**　在任务中为人保留审核、纠错或接管的环节，例如超过授权额度的退款交给人工审批。

**幂等（Idempotency）**　同一操作重复执行结果一致；Agent 超时重试前先查状态，写操作要带幂等键。

**沙盒（Sandbox）**　隔离文件、网络和资源，限制 Agent 能碰什么；跑生成代码和不可信工具时必备。

**技能（Skills）**　用 SKILL.md 写清什么时候、怎么做的可复用流程，按需加载；比把规则全塞进系统提示更省上下文。

> SDD 常见实现：[Spec Kit](https://github.com/github/spec-kit)（规格工作流）、[OpenSpec](https://github.com/Fission-AI/OpenSpec)（变更提案）、BMAD（角色流程）、superpowers（可组合技能）。

## Agent 开发与产品实践

### 产品设计：从用户任务到授权边界

**场景筛选**　先陪用户走完一单，优先挑频率高、系统有数据、结果可核验的任务，例如查退款进度。

**人工基线（Baseline）**　先记录人工处理同类任务的耗时、一次解决率和出错成本，上线后才能判断 Agent 改善了什么。

**任务验收条件（Acceptance Criteria）**　把「办好退款」写成可检查的结果，例如金额正确、退款单已创建、用户收到回执。

**自主程度（Agent Autonomy）**　逐项约定 Agent 可以查询、起草还是直接执行，例如查进度可自动完成，发起退款按授权额度处理。

**澄清提问（Clarifying Questions）**　只追问会改变下一步的信息，例如用户有两笔同金额订单时，请他选定要退的那一笔。

**执行预览与确认**　在提交前展示操作对象、金额和后果，并把用户确认绑定到这次具体操作，关键参数变化时重新确认。

**人工交接（Handoff）**　转人工时带上用户诉求、已核实的信息、已执行的动作和待解决的问题，让用户免于重述。

### 工程实现：让任务可靠执行

**工具契约（Tool Contract）**　约定工具用途、必填参数、返回值和错误类型，让 Agent 能区分「查无订单」和「订单系统暂不可用」。

**任务状态机（State Machine）**　用明确的状态和转换规则管理任务，例如退款申请只能从「待确认」进入「提交中」，随后依据回执更新状态。

**运行检查点（Checkpointing）**　保存任务进度、已确认的参数和外部操作编号，服务重启后据此核对订单并继续执行。

**委托授权（Delegated Authorization）**　让 Agent 在用户授予的身份和权限范围内调用业务系统，例如仅能查询该用户自己的订单。

**错误恢复（Error Recovery）**　按失败原因选择下一步，例如缺参数就追问，暂时限流就退避，提交超时就先查原单状态。

**补偿操作（Compensating Action）**　多步任务部分成功时，用业务允许的逆向操作消除已产生的影响，例如订票失败后释放已占座位。

**执行预算（Execution Budget）**　为一次任务设定时长、工具调用次数或费用上限，耗尽时交付已核实的进展并说明卡在哪里。

**取消语义（Cancellation）**　区分停止后续步骤与撤销已生效的操作，例如用户点停止时，已提交的退款仍须查询并告知状态。

### 评测与上线：判断能否放心交付

**结果验证（Outcome Verification）**　运行结束后直接检查业务系统，例如验证目标订单确实出现一笔金额正确的退款记录。

**轨迹评测（Trajectory Evaluation）**　检查执行记录中业务必需的步骤，例如退款前是否核验资格，同时允许不同的合规执行路径。

**重复运行一致性（pass^k）**　每道任务在相同初始条件下独立运行 k 次，统计每次都成功的任务占比，衡量用户反复使用时的可靠性；和只看「至少成功一次」的 pass@k 不同。

**失败归因（Error Analysis）**　从第一个偏离预期的步骤定位原因，例如区分选错工具、参数填错、外部接口失败和验收规则误判。

**影子模式（Shadow Mode）**　让新版本处理真实请求的副本，隔离外部写入，再将拟采取的动作与实际处理结果比对。

**自主解决率（Autonomous Resolution Rate）**　用无需人工接手且达到验收标准的任务数除以纳入统计的任务数，事先约定例行审批是否算人工介入。

**人工净节省时间**　用同类任务原先的人工耗时减去上线后的审核、接管与返工耗时，例如原需 10 分钟、现需人工 3 分钟，净省 7 分钟。

延伸阅读见 [LangGraph 状态持久化](https://docs.langchain.com/oss/python/langgraph/persistence)、[Anthropic 智能体评测实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) 和[美团商家 AI 助手评测案例](https://tech.meituan.com/2026/11/17/Agent-Evaluation-White-Paper-02.html)。

## 协议与生态

**MCP（模型上下文协议）**　用 JSON-RPC 连接 AI 应用与外部工具、数据的开放标准；2026-07-28 版改为无状态请求/响应核心，授权认证向 OAuth/OIDC 实践对齐。

**MCP 客户端与服务端**　客户端在宿主里管连接，服务端提供工具、资源、提示词；权限由服务端校验，宿主决定给模型看哪些工具。

**多轮请求（MRTR）**　工具执行中缺信息时，服务端返回 `resultType: "input_required"`，并给出 `inputRequests` 或 `requestState`；客户端用新请求 ID 重试，原样带回 `requestState`，并在 `inputResponses` 中逐项回应。

**MCP 扩展与弃用**　Tasks 等能力移出核心、改为按需扩展；Roots、Sampling、Logging 标为弃用。

**A2A（Agent2Agent）**　智能体之间协作的协议：用 Agent Card 描述能力，发消息、跟踪任务、收产物；MCP 接工具，A2A 接智能体。

**Agent Card**　A2A 里的「名片」：能力、技能、认证方式和端点；先查名片再决定要不要委托。

**Agent Skills 标准**　一个文件夹加 SKILL.md 的开放格式，2025-12 发布，70 多个平台接入（ChatGPT、Cursor、Copilot、VS Code 等）；2026-10 捐给 AAIF 托管。

**AGENTS.md**　给编程 Agent 的项目说明，写命令、约定和禁区；Codex、Cursor 等已支持。

**AG-UI**　智能体和前端之间的事件协议，把流式输出、工具调用状态推给界面；常与 MCP、A2A 搭配。

**AP2（Agent Payments Protocol）**　Google 牵头的智能体支付协议，用可验证凭证表达谁授权、买了什么；60 多家机构参与。v0.2 增加「人不在场」的预授权支付，和 UCP 互补。

**ACP（Agentic Commerce Protocol）**　OpenAI 和 Stripe 的智能体电商协议，ChatGPT 的 Instant Checkout 用它。

**UCP（Universal Commerce Protocol）**　Google 的通用电商协议，覆盖商品、身份和订单；和 ACP 抢同一场景。

**ANP（Agent Network Protocol）**　面向开放网络的智能体协议，用 did:wba 做去中心化身份。

**AAIF（Agentic AI Foundation）**　Linux 基金会下的中立治理机构，2025-12 成立，托管 MCP、A2A、Agent Skills、AGENTS.md、OpenEnv 等约十个项目。

**OpenEnv**　智能体执行环境的开放接口（reset、step、state），用来训练和评测 Agent；训练环境要尽量贴近生产。

**开源权重（Open Weights）**　权重可下载，但许可证可能限制商用和再分发，不等于 OSI 定义的开源；如 Qwen3.5、DeepSeek V4、Kimi K3、GLM-5.2。

**闭源模型**　只能通过 API 或产品使用；数据、日志、限流都由服务商控制，如 GPT-6、Claude Opus 5.5、Gemini 4；版本更迭快，比较看当期评测。

**Hugging Face**　模型和数据集的 GitHub，也是 Transformers 等库的家；用前看清许可证。

**框架与平台**　LangChain 用代码搭 Agent，Dify 做低代码 RAG 和工作流，n8n 做自动化编排；先手写循环再用框架。

**OpenClaw**　MIT 许可、可自托管的个人 AI 助手：Gateway 接聊天软件，运行时调模型和工具，工作区 Markdown 存记忆，技能用 SKILL.md 描述。

## 检索与知识（RAG）

**知识库（KB）**　组织知识、支持查询的系统；企业里常指 RAG 的资料库，不等于模型已经记住。

**RAG（检索增强生成）**　先检索资料再让模型据此回答；解决「不知道」和「过期」，不解决「不听话」。

**索引（Indexing）**　离线把文档切块、转向量、入库；索引不更新，回答就会用旧规。

**分块（Chunking）**　把长文档切成可独立检索的片段，例如让表头与对应的数据行保存在一起；给每块补一句文档级上下文（上下文检索）能减少断章取义。

**元数据（Metadata）**　来源、时间、部门、权限等字段；过滤和排序都靠它。

**向量数据库**　存向量并做近邻检索；Milvus、Qdrant、pgvector 等。

**ANN / HNSW**　近似最近邻索引，用一点召回率换速度；数据量大时必用。

**BM25**　关键词检索的经典算法；型号、编号、专有名词靠它更稳。

**混合检索（Hybrid Search）**　关键词和向量一起召回，再用 RRF 等融合；工程上通常比单一路径稳。

**重排序（Rerank）**　对已召回的候选结果再次评分，把更能回答问题的片段排在前面，交叉编码器是常用方法。

**查询改写（Query Rewrite）**　把口语问题改成适合检索的查询；多轮对话里尤其必要，HyDE 是其中一种写法。

**Agentic RAG**　让 Agent 自己决定查什么、查几次、够不够；比固定流水线灵活，也更贵更难测。

**GraphRAG**　抽实体和关系建图再检索；适合跨文档总结和关系型问题。

**知识图谱（KG）**　结构化的事实网络，实体—关系—实体；可校验，但构建和维护成本高。

**权限检索（Permission-aware Retrieval）**　按用户的访问权限筛选检索结果，只有获准读取的内容才能进入模型上下文。

**引用溯源（Citation）**　把结论连到原文片段；用户能核对，系统能评估是否有据。

**证据支撑（Grounding）**　把回答中的主张与可核验的信息对应起来，例如用实时库存查询结果回答「还有货吗」。

**召回率与精确率**　召回是找回的相关项除以全部相关项，精确是相关项除以返回项；RAG 先保召回，再谈排序。

**长上下文 vs RAG**　资料少且固定，直接塞进上下文更简单；资料多、常更新、要权限，才上 RAG。

## 评测、可观测与安全

### 评测

**评测集（Eval Set）**　一组可重复的题，含典型、边界和已知失败样例；黄金集是人工确认过标准答案的子集。

**回归评测**　换模型、提示或检索后重跑同一批题，看原来对的有没有变错。

**RAG 评测**　分开评检索命中、引用正确和回答有据；只看最终答案会掩盖检索问题。

**pass@k**　k 次尝试里至少一次通过的比例，衡量「能不能做出来」；和 pass^k（每次都成功）不同，后者衡量可靠性。

**LLM-as-Judge**　让模型按评分准则打分；便宜但有偏好，要用人工样本校准。

**评分准则（Rubric）**　把「答得好」拆成可判定的条件；不写清楚，裁判和人都没法一致。

**任务完成率（Task Success Rate）**　达到验收条件的任务数除以发起的任务数，例如一笔订单重试后出票，仍算一个成功任务。

**采纳率（Acceptance Rate）**　用户采纳的建议数除以展示数；写作、编程助手的真实体感指标。

**单次成功任务成本（Cost per Successful Task）**　全部尝试的总成本除以成功任务数，便于比较重试和人工返工后的实际成本。

**数据污染与基准饱和**　测试题泄漏进训练集会虚高；MMLU 等老基准已接近满分，区分度下降。

**A/B 测试**　随机分流比真实指标；离线评测好不等于线上好用。

**可观测性（Observability）**　上线后能看请求、工具调用、成本、错误和延迟；日志要能按会话串成 trace，否则出了事查不动。

**调用链追踪（Tracing）**　把检索、模型、工具调用串成一条链，定位错在哪一步；OpenTelemetry 有 GenAI 语义约定。

**数据飞轮**　把线上使用和反馈变成新评测、新训练数据；没有闭环，模型不会自己变好。

**可解释性（XAI）**　能说明模型为什么这样答；LLM 时代主要靠引用、trace 和评测，而不是特征归因。

### 常见评测基准

**MMLU**　学科知识选择题。已饱和，只适合看下限。

**GPQA**　研究生级问答。难，但仍可能被背题。

**AIME**　数学竞赛。推理模型刷新最快。

**HLE**　跨学科极难题。当前最硬的通用榜之一。

**ARC-AGI-2**　抽象推理。测没见过的新规则。

**SWE-bench Verified / Pro**　真实仓库改代码。Verified 有污染争议，Pro 更难。

**Terminal-Bench**　终端里完成任务。测 Agent 工程能力。

**τ²-bench**　多轮工具与对话。测工具使用和规则遵循。

**OSWorld / WebArena**　操作电脑和网页。计算机使用的标准测试。

**GAIA**　真实助理任务。需要检索加工具组合。

**LMArena**　人类偏好投票，用 Elo/Bradley–Terry 排名；热门但可被刷榜和风格偏好影响，别只看排名。

### 安全与合规

**提示词注入（Prompt Injection）**　输入中的指令诱导模型偏离应用原定任务，可直接来自用户，也可间接藏在网页、文档或工具结果中；OWASP 把它列为 LLM 风险第一位。

**致命三要素（Lethal Trifecta）**　私有数据、不可信内容、对外发送能力同时存在，就有被套取数据的风险；缺一可大幅降险。

**越狱（Jailbreak）**　用话术绕过模型安全策略；和注入不同，目标是让模型说不该说的。

**工具投毒（Tool Poisoning）**　恶意工具描述或返回内容诱导模型调用危险操作；接第三方 MCP 服务器要审。

**过度代理（Excessive Agency）**　给了 Agent 超出任务需要的权限；最小权限、白名单、人工确认是解。OWASP 2026 把它升到第三位。

**护栏（Guardrails）**　输入输出两侧的规则和模型检查；能挡明显问题，挡不住精心设计的攻击。

**系统提示泄露 / 隐藏上下文暴露**　攻击者套出系统提示、开发者指令、检索到的策略文本或工具定义；OWASP 2026 把范围从「系统提示泄露」扩为「隐藏上下文暴露」。提示词里不要放密钥和真正的权限逻辑。

**PII 与脱敏**　个人身份信息；进模型前脱敏，日志里也别存原文。

**红队（Red Teaming）**　上线前主动攻击：越狱、注入、诱导危险工具；Agent 还要测被说服的边界。

**水印与 C2PA**　标记 AI 生成内容来源；C2PA 是内容凭证标准，平台和相机厂商在用。

**内容标识**　中国《AI 生成合成内容标识办法》自 2025-09-01 施行，要求显式标识和隐式标识（元数据）。

**大模型备案**　面向公众提供生成式 AI 服务，按《生成式人工智能服务管理暂行办法》做备案和安全评估；企业内部使用与对外服务要求不同。

**EU AI Act**　欧盟人工智能法案；GPAI 义务 2025-08-02 生效，独立高风险系统延到 2027-12-02，嵌入产品的高风险系统延到 2028-08-02。

**OWASP LLM Top 10**　应用安全清单；2026 版仍以提示注入居首，过度代理升到第三，系统提示泄露扩为隐藏上下文暴露。

## 多模态与生成

**视觉语言模型（VLM）**　同时理解图像和文本；能描述、问答、读图表。

**原生多模态**　训练时就把文本、图像、音频放在一起，而不是外挂编码器；Gemini 是代表。

**全模态（Omni）**　输入输出都支持多种模态，包括实时语音；适合语音助手。

**ASR（自动语音识别）**　语音转文字；会议纪要、字幕、语音输入。

**TTS（文本转语音）**　文字转语音；现在的模型能做情感和语气。

**说话人分离（Speaker Diarization）**　按声音标出每段发言的起止时间和说话人编号，姓名需要额外核实；会议纪要的「谁说了什么」靠它。

**实时语音（Speech-to-Speech）**　直接语音进、语音出，延迟低、能打断；比 ASR 到 LLM 再到 TTS 自然。

**OCR（光学字符识别）**　图片或扫描件转可检索文本；票据、证件、合同。

**文档解析（Document AI）**　版面、表格、公式、阅读顺序；RAG 效果差常卡在这一步。

**生成式 AI / AIGC**　生成文本、图像、音频、视频的 AI 及其产物；现在说 AIGC 多指图像和视频。

**Flow Matching**　扩散模型（见[神经网络](#神经网络)）的改进训练目标，采样步数更少；新模型常用。

**DiT**　用 Transformer 做扩散主干，替代 U-Net；视频生成的主力架构。

**文生图与图像编辑**　生成和改图；参考图、局部重绘、风格迁移。

**局部重绘（Inpainting）**　用蒙版指定希望重绘的区域，例如移除路人；边缘、光影和反射要额外检查。

**角色一致性**　跨镜头保持同一张脸和服装；AI 短片的验收标准。

**文生视频**　生成视频片段；运镜、首尾帧、参考视频控制。

**常用生成模型**　图像可选 Nano Banana，视频可选 Veo、可灵，选型时用同一份素材比较可控性和成本。

**Seedream**　字节跳动的图像生成与编辑模型，可用参考图制作海报，再用文字调整画面。

**Seedance**　字节跳动的视频生成模型，可用参考图指定角色、用参考视频示范运镜。

**世界模型（World Model）**　预测动作之后世界会怎样；Genie、Marble 这类可交互世界生成，用于具身和自动驾驶仿真。

**VLA（视觉—语言—动作模型）**　看图、听指令、直接输出机器人动作；具身智能的主流路线。

**具身智能（Embodied AI）**　有身体、能形成感知—行动闭环的智能；难点在真实世界的泛化和安全，仿真到真机还有 sim2real 差距。

**AI4S（AI for Science）**　用 AI 做科研：蛋白结构、材料、数学猜想；近年产出密集。

## 日常与工作

### 工作里

**Copilot**　嵌在现有工具里的 AI 助手形态；优势是自带上下文，不是另一个聊天窗口。

**POC（概念验证）**　小范围验证可行性；AI 项目要同时验证效果、成本和权限。

**私有化部署**　模型和数据放在自己的环境；金融、政务常见，代价是运维和更新慢。

**SOP**　标准操作流程；做 Agent 前先把流程写成 SOP，否则模型只能猜流程。

**数字孪生**　现实对象的虚拟映射，用实时数据同步；用于监控、仿真和预测。

**RPA**　机器人流程自动化，按固定规则点界面；和 Agent 的区别是规则写死还是临场决策。

**GEO / AEO**　生成引擎优化、答案引擎优化：让内容更容易被 AI 搜索引用；SEO 的 AI 版。

**AI 原生（AI-native）**　交互、数据和流程都按模型能力重新设计，而不是给旧功能加个聊天框；判断标准是去掉模型后产品还剩什么。

### 日常

**AI 搜索**　先检索再总结并给链接；适合需要综合判断的问题，但要看原始来源。

**Deep Research（深度研究）**　多轮检索、交叉验证、输出带出处的报告；适合竞品和文献调研。

**Gemini Notebook（原 NotebookLM）**　围绕指定资料问答并给出出处，适合查阅项目文档或复习课程。

**会议纪要**　ASR、说话人分离、摘要和待办抽取；准确率取决于麦克风和术语。

**信息抽取**　从非结构化文本里取字段；发票、合同、简历。

**AI 陪伴**　情感对话产品；注意依赖、隐私和内容边界。

**AI 眼镜 / AI PC / AI 手机**　把模型放到端侧或随身设备；卖点是实时、隐私、低延迟，不是参数量。

**自动驾驶分级**　L2 辅助驾驶、人负全责；L3 在限定条件下由系统驾驶，责任划分看法规；L4 限定区域可无人，L5 全域无人。宣传里的「全自动驾驶」要对照等级和责任。

**AI slop**　低成本批量生成的劣质内容；识别它正在成为基本媒介素养。

**深伪（Deepfake）**　换脸或克隆声音；转账、验证身份时要多重确认。

**智能体电商**　让 Agent 替你比价、下单、付款；协议是 ACP、UCP、AP2，风险在授权和退款。

## 面试速答

### 常见问题

**长上下文能替代 RAG 吗？**

不能。窗口解决「放得下」，RAG 解决「找得到、更新快、有权限」；资料少且固定时直接塞更简单。

**什么时候微调，什么时候提示词或 RAG？**

学风格格式用微调，补知识用 RAG，改行为靠提示词加评测；多数问题先从数据和提示入手。

**什么时候用 Agent，什么时候用工作流？**

审批步骤和分支明确时用工作流，需根据新结果持续选择下一步时可用 Agent，并设置预算和停止条件。

**怎么证明你的 AI 功能有效？**

固定评测集加回归，再加线上指标（完成率、采纳率、单位成本）；换模型或提示都要重跑。

**幻觉怎么降？**

检索给证据、强制引用、结构化校验、允许说不知道；只写「请勿编造」没用。

**怎么防提示词注入？**

外部内容当数据不当指令、最小权限、危险操作人工确认、输出侧校验；没有银弹。

**Agent 卡住或跑飞怎么办？**

步数、时间、成本上限，重复检测，失败回滚，人工接管；状态要持久化。

**成本怎么算？**

算单位成功任务成本，含重试和人工；再看缓存命中、模型路由和批处理。

**上线后效果变差怎么查？**

先看 trace 定位检索、工具、模型哪一步，再查数据漂移和提示变更。

**模型的能力边界在哪？**

擅长模式匹配和生成，不擅长保证事实、长期规划和精确计算；这些用工具和验证补。

### 容易被追问的说法

**「参数量越大越聪明」**

看数据、后训练和任务匹配；小模型在窄任务上常更划算。

**「上下文 1M 就能读 1M」**

有效上下文更短，长文中间容易丢；要测自己的材料。

**「RAG 就不会幻觉」**

检索错、切分错、读错都会幻觉，检索和生成要分开评。

**「微调能灌知识」**

知识靠检索，微调主要改行为和格式，且容易忘旧知识。

**「温度 0 结果就固定」**

批处理、硬件和算子差异仍可能带来波动。

**「Agent 就是会聊天的模型」**

Agent 的核心是循环、工具、状态、权限和停止条件。
