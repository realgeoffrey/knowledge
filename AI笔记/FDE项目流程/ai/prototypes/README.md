# 静态交互稿与评审说明

> **AI维护｜页面任务按需读取。** 人通过待澄清问题里的直接链接评审。

## 先选入口

- [规范示意页](design-system.html)：看风格、功能模式、列表和表单；默认紧凑密度，可切标准密度，大屏按需展开。模式索引不代表已实现。核对筛选、详情、新增、0/空字段、校验、失败和重置。
- [业务交互稿](pages/index.html)：评审业务路径，目前是下方虚构采购示例。

规则唯一来源是 [设计规范](../specs/design.md)，原型只呈现规则。默认 Vue 3 + Element Plus 参考不代表固定工程或 G2 已过；规范采纳和版本按 [设计维护步骤](../specs/design.md#修改与项目确认)，客户批准只记 [验收记录](../records/acceptance.md)。

## 静态页面生成规则

- 业务 HTML 与本地资源放 `ai/prototypes/pages/`，固定入口 `pages/index.html`，资源按需放 `pages/assets/`。不在原型根散放业务 HTML，也不复制设计规范。
- 规则源为 `ai/specs/design.md`，规范展示为 `ai/prototypes/design-system.html`。页面用相对链接离线互通：规范页 → `pages/index.html`，业务页 → `../design-system.html`。
- 先读相关设计章节/tokens、REQ/AC、有效基线和本次范围，复用已采纳代表页；无项目样板时用采购例的表达方式，不继承其业务规则。设计缺口才查 [按需参考](../handbook/ui-reference.md)。

1. HTML/CSS/少量原生 JS 双击可用，无网络、构建或真实系统写入；使用设计 CSS 变量，不逐控件配色，共享资源进入原型固定清单。
2. 按已选 Element Plus / Ant Design 模式表达列表、表单、详情与审批；无工程时默认 Element Plus。原生控件表达语义，不安装组件库、Tailwind、外部字体，不自造交互机制。正式组件/主题差异按 [库映射](../handbook/ui-reference.md#ruoyi-迁移约束) 写 [方案](../specs/solution.md#设计落地与页面验证)，不将整页 HTML、模拟权限或内存数据层搬进正式系统。
3. 只生成约定业务和适用状态，未知标待确认，未演示注明；显示项目名、PAGE/REQ、需求/原型版本、演示数据标记，规范页标设计版本与批准状态。需求前不虚构编号或批准。
4. 提供本期加载、空、错误、无权限、冲突等反馈，场景可重置并说明刷新丢失数据。实际渲染检查主流程、异常、重置、约定视口、长文本/0、对齐、对比度、焦点与表单错误；共享主题变化复核受影响代表页。
5. 重生成页面保留 `DESIGN_TOKENS_START/END`、`design-version`、`data-design-version` 槽。`ai/prototypes/` 内全部 HTML 均须登记到同步脚本 `PAGE_FILES`，遗漏会在检查或写入前失败；不存手工 token 副本。在项目根执行 `python3 ai/scripts/sync_design.py`、`python3 ai/scripts/sync_design.py --check`；同步不证明布局、行为或框架兼容，实际检查结果和未覆盖项记下方。

模板 [采购申请](pages/index.html) 覆盖列表、实时筛选、录入、详情与审批，[规范页](design-system.html) 补充密度对照。复制后按实际终端、组件库和范围验证，仅固定采用片段，不逐页生成设计报告。

## 当前业务交互稿是示例

- 原型 P1.0 / 需求 R1.0 为虚构标签，无客户批准。员工提交、主管审批、按角色看记录；内存保存，刷新或重置恢复初始数据，权限/审批仅前端模拟。
- 不含 R1.1 大额加签、草稿编辑、撤回、重提、导入导出、真实附件、网络加载和故障情景。真实系统的重复请求、并发、事务、范围外 ID、外部接口、历史兼容另测。
- 启用真实项目时替换业务和版本，补齐本期场景；示例不算真实编号、兼容、安全或验收证据。

## 示例页面与需求

| 页面 | 关联需求 | 交互 |
| --- | --- | --- |
| PAGE-001 列表 | REQ-001 / REQ-003 | 员工甲看自己，主管甲看研发部；搜索、空态、详情 |
| PAGE-002 新建 | REQ-001 | 填事项和金额，校验后提交 |
| PAGE-003 详情/审批 | REQ-002 / REQ-003 | 主管处理本部门他人待审申请，驳回必填原因 |

金额大于 0、最多两位小数、上限 99,999,999.99；事项最多 60 字。主管不能自审批，最终状态不可再次处理。

## 建议评审路径

1. 员工甲看列表/详情，确认仅见自己的记录。
2. 新建输入 0、负数、三位小数，检查错误，再合法提交。
3. 回列表搜索新申请，核对状态。
4. 切主管甲通过新申请，再由员工甲查询结果。
5. 驳回另一待审申请，先验证空原因被阻止，再填写完成。
6. 主管查看自己申请，确认不可自审批。
7. 切“模拟失败”的无权限/状态冲突，确认失败反馈且数据不变；恢复后处理。
8. 搜索不存在内容看空态，重置后重跑。
