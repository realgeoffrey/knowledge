# 开发与质量：G3 / G4

> AI维护，按任务读取。阶段条件见 [八步流程](../../README.md#八步流程)；实现决定和实际命令写 [方案](../specs/solution.md)，需持久交接时复用已有任务入口或用 [TASK](../tasks/TEMPLATE.md)。

## 1. 固定工程，验证基础链

固定前后端仓库/目录/完整 commit、模块、运行环境版本、功能开关及理由；记录命令工作目录、依赖、证据和干净检出已有的失败。按实际构建说明、`pom.xml`、`package.json`、锁文件确定命令，不猜脚本，也不混用若依分支或凭“最新版”判断兼容。[官方入口](references.md#官方资料) 供按版本核查。

用虚构数据跑通：**启动→普通账号登录→菜单/按钮→业务接口→数据读写→另一角色被限制→有断言测试**。目标测试须实际执行；零测试、跳过不算通过。无前端测试设施时记录关键交互人工验证，再按风险补最小方案。

## 2. 复用架构与工程能力

默认模块化单体，沿用相邻代码分层，复用用户、角色、部门、菜单、字典、文件，不为单客户规则改框架内核。固定审批先用状态转换，可配置节点/会签/委派再评估 BPM；微服务、中间件、多租户须有业务理由。

启用多租户后验证表、查询、缓存、文件、导出隔离。生成器仅供 CRUD 骨架，仍核对字段、权限、菜单、业务校验和测试；再次生成先预览差异，不覆盖业务代码。

## 3. 数据、接口与权限的最低设计

| 方面 | 必查 |
| --- | --- |
| 数据 | 字段、精度、时间口径、非空/唯一/索引、枚举、归属、逻辑删除、审计 |
| 后端 | 核验或推导身份、归属、审批人、状态、计算结果，不信任前端输入 |
| 写入 | 合法转换、事务、失败回滚、重复操作、并发 |
| 历史 | 旧数据/在途规则，迁移顺序、前置条件、夹具、验证查询 |
| 接口 | REQ、方法/路径、请求响应、校验、权限/范围、错误、幂等、调用方 |
| 权限 | 菜单、按钮、API、记录、敏感字段；覆盖详情、修改、下载、导出 |

字段引用现有 OpenAPI，不存副本。数据变更在空库和含旧数据的测试库验证；SQL、锁、事务须在目标数据库验证。新业务核对数据权限及适用的租户机制，隐藏按钮或只过滤列表不能防止直接访问范围外 ID。

持久数据或外部契约变更另核支持旧版到目标版的连续升级，保留实际已执行迁移及脚本版本/校验和；失败恢复、不可逆边界和兼容退场条件写方案，证据只记 RUN，沿用既有迁移/上线流程。破坏性接口或表结构按需先扩展兼容、迁移调用方/数据，再确认退出旧入口；代码回退不等于数据恢复。

## 4. 按改动范围完成业务路径

开发新业务路径时，按已确认 REQ/AC 核对范围与依赖，读相邻实现和调用方，验证受影响层的正常、失败和关联场景。改动跨前后端、权限或数据时，用真实测试链验证闭环。

简单文案、布局或局部修复做针对性检查即可；按 [维护触发条件](maintenance.md#1-何时检查谁执行) 更新必要记录。设计修改按 [维护步骤](../specs/design.md#修改与项目确认)，同步脚本不证明页面行为或客户验收。

## 5. 新意见先分类

此规则贯穿所有阶段：

| 类别 | 判断与处理 |
| --- | --- |
| 澄清 | 不改已确认行为，补说明/来源，原测试仍成立 |
| 缺陷 | 违反有效规则，复现、修复、回归。S0/S1 和违反已确认承诺记 BUG；其余缺陷在跨会话跟进、影响有效 AC 或进入验收时再关联 BUG |
| 变更 | 改已确认角色、字段、权限、状态、口径、范围或视觉/交互承诺，走 CR |
| 待定想法 | 留待办，不自动纳入本期 |

按承诺变化分类，不按改动大小。草稿直接迭代；不触及承诺或行为的微调沿用已有任务入口即可。客户方向性赞同不算批准；OPEN 关闭不代替 CR 批准、实现或验证。

## 6. CR 闭环与影响分析

按 [CR 模板](../changes/TEMPLATE.md) 记录原规则→拟规则、边界和生效时间，用下表筛查实际影响。保留相关维度、工作量与取舍；旧数据、在途、权限等容易漏判时，即使无影响也简记依据。沿调用关系核对，关键词未命中不能证明无间接影响。

| 维度 | 核对线索 |
| --- | --- |
| 需求/页面 | 场景、角色、表单/详情/筛选/提示、待办/统计、已批准视觉交互、后台/大屏范围 |
| 设计/资源 | 规范章节、tokens、主题映射、共享 CSS/图标/字体、受影响页面 |
| 接口/联动 | 请求响应、错误、枚举、导入导出、外部兼容；消息/缓存/任务/菜单/字典 |
| 数据/权限 | 字段约束、规则版本、旧数据/在途；个人/部门/租户、敏感字段/附件 |
| 状态/写入 | 合法转换、回滚、重复/并发/重试 |
| 验证/交付 | AC、测试、UAT、依赖、工期费用 |

固定候选包→客户确认差异与代价→按 [基线生效核对](../records/acceptance.md) 合并并切换 BL→实现与回归→客户复验后关闭 CR。批准前保留当前 BL；晚到批准不能直接覆盖，原包与证据保留。相同规则复验不再审批，新增业务差异另确认。

## 7. 按风险验证，不削弱断言

复用现有设施：规则/服务验证金额、状态、重复与失败；接口/数据库验证授权链、范围外 ID、约束、回滚、并发、旧数据；前端验证校验、条件显示、反馈、接口失败；少量端到端覆盖普通账号创建→处理→查询，人工/UAT 补真实习惯与样本。

高风险 AC（权限、金额、状态、批量/外部写入、迁移）保留可靠测试，其他 AC 至少可复现；不只测管理员，不用覆盖率代替正确性。

- 有效承诺保留旧测试；经 CR 改变时关联批准来源、修改预期并保留边界反例。
- 取消需求保留决定，仅删除专属用例并说明替代关系。
- 修缺陷先复现，尽可能证明同一用例修复前失败、修复后通过。
- 环境不足记未运行、原因、补测时间与外部条件，保持未验证。

任务检查直接及关联影响，集成前跑稳定核心回归，UAT 前核对全部有效 AC；文档无需全系统回归，共享权限或模型变化须扩大检查。设计按约定环境复核。正式证据按 [RUN 规则](../records/traceability.md#验证证据按执行批次添加) 保存，未验证不报通过。采购样例的核心反例见 [示例](references.md#example)，不得把旧规则断言一律改成新规则。

## 8. 只读复核与缺陷处理

从需求/AC 对照实现。高风险改动要有独立的复核视角，优先用反例、可执行断言和实际证据；涉及权限、不可逆迁移等且仍有不确定性时，请人或另开只读会话复核。核实发现并补针对性检查；意见一致不代替证据。

| 等级 | 例子 / 处理 |
| --- | --- |
| S0 | 越权、租户泄漏、不可恢复破坏；阻断交付 |
| S1 | 核心流程、关键计算或审批错误；阻断交付 |
| S2 | 次要功能有替代；修复或客户明确接受遗留 |
| S3 | 不影响操作理解的样式/文案；可约定后续 |

遗留须记录影响、替代、动作、日期与客户确认；有效 AC 失败仍须修复或正式调范围。移除功能须确认范围并验证其他路径不依赖它；口头同意上线不能豁免 S0/S1。

## 9. 教训只留可执行的防错动作

有根因证据且可防返工才建 `ai/LESSONS.md`：LESSON、Scope、active 状态、根因、防错动作、CR/TASK/TEST/commit、替代防错入口及 RUN，复发时追加日期。未验证如实注明，不记普通 Bug，不预建。

访谈、原型、缺陷、跨模块、权限/数据高风险任务只检索相关 active 条目，旧教训不覆盖现行规则。优先固化测试，技术/业务/架构结论分别回规范/需求/方案；合并同根因，已固化条目保留替代证据后归档 `ai/lessons/archive/`，失效标明。不删尚无替代验证的严重风险，跨客户仅复用脱敏模式。
