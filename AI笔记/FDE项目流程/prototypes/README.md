# 静态交互稿与评审说明

> **AI 维护，页面任务按需读取。** 提交评审时在对话中附受影响页面的直达链接。

## 先选入口

- [规范示意页](design-system.html) 提供分章目录、布局骨架、状态映射和交付检查。从列表打开录入或详情抽屉，核对关闭后的筛选、位置和焦点；详情内可连续打开三层，检查逐层返回及父层输入保留。大屏按需展开。
- [业务交互稿](interactive/index.html)：评审业务路径，目前是下方虚构采购示例。

设计规则唯一来源是 [design.md](design.md)，业务规则以 [spec](../spec/README.md) 为准；示例不构成客户批准。

## 静态页面生成规则

- 业务 HTML 与本地资源放 `prototypes/interactive/`，固定入口 `interactive/index.html`，资源按需放 `interactive/assets/`。不在原型根散放业务 HTML，也不复制设计规范。
- 规则源为 `prototypes/design.md`，规范展示为 `prototypes/design-system.html`。页面用相对链接离线互通：规范页 → `interactive/index.html`，业务页 → `../design-system.html`。
- 从目标页面、相邻样板和适用设计章节开始；改到业务语义、共享依赖或客户承诺时再展开相关 REQ/AC 与现行业务规格。无项目样板时参考采购例的表达方式，不继承其业务规则。设计缺口再查设计规范中的相关章节。

1. HTML/CSS/少量原生 JS 双击可用，无网络、构建或真实系统写入；使用设计 CSS 变量，不逐控件配色，共享资源进入原型固定清单。
2. 按已选 Element Plus / Ant Design 模式表达列表、表单、详情与审批；无工程时默认 Element Plus。原生控件表达语义，不安装组件库、Tailwind、外部字体，不自造交互机制。正式组件/主题差异按实际组件库文档写 [实现补充](../ai/README.md)，不将整页 HTML、模拟权限或内存数据层搬进正式系统。
3. 页面呈现本期业务和适用状态。材料有缺口时，在授权和现行业务规格内选取有依据、可逆的做法直接呈现，在对话中说明实际采用的行为和演示范围。页面显示项目名、适用规格链接、演示数据标记，规范页标设计版本与实际批准状态。
4. 提供本期加载、空、错误、无权限、冲突等反馈，场景可重置并说明刷新丢失数据。按 [原型交付检查](design.md#原型交付检查) 实际渲染并验证代表路径。共享主题变化复核受影响代表页。
5. 重生成页面保留 `DESIGN_TOKENS_START/END`、`design-version`、`data-design-version` 槽。`prototypes/` 内新 HTML 均登记到同步脚本 `PAGE_FILES`，不存手工 token 副本。只在 tokens、规范版本或页面登记变化时按 [设计维护](design.md#设计维护) 同步。生成槽、登记或链接变化时跑结构检查；小改复核实际受影响的页面，模拟边界与未覆盖项记下方。

模板 [采购申请](interactive/index.html) 覆盖列表、实时筛选、录入、详情与审批。两页共用 [抽屉样式](interactive/assets/drawer.css)和[层叠交互](interactive/assets/drawer.js)，当前为候选 DESIGN D1.13。默认宽度由设计 tokens 同步；新抽屉用 `DrawerLayers.open(dialog)` 打开，关闭、取消、Esc 或遮罩只退一层，保留父层 DOM、输入、滚动和焦点。页面跳转或角色切换先调用 `DrawerLayers.closeAll()`。桌面子层按父层宽度减 48px 收窄（最小 320px），窄屏全宽。复制后按实际终端、组件库和范围验证，仅固定采用片段。

## 当前业务交互稿是示例

- 当前业务交互稿仅为虚构示例，无客户批准。员工提交、主管审批、按角色看记录；内存保存，刷新或重置恢复初始数据，权限/审批仅前端模拟。
- 不含大额加签、草稿编辑、撤回、重提、导入导出、真实附件、网络加载和故障情景。真实系统的重复请求、并发、事务、范围外 ID、外部接口、历史兼容另测。
- 启用真实项目时替换业务和入口，补齐本期场景；示例不算真实编号、兼容、安全或验收证据。

## 示例页面与需求

| 页面 | 演示内容 |
| --- | --- |
| 申请列表 | 员工甲看自己，主管甲看研发部；搜索、空态、详情 |
| 新建申请 | 填事项和金额，校验后提交 |
| 申请详情与审批 | 详情内打开审批抽屉，可再查看申请记录；主管处理本部门他人待审申请，驳回必填原因 |

以下采购行为仅属于原型示例，不写入真实项目规格。金额大于 0、最多两位小数、上限 99,999,999.99；事项最多 60 字。主管不能自审批，最终状态不可再次处理。

## 建议评审路径

1. 员工甲筛选列表后打开详情，确认仅见自己的记录。用 Esc 或关闭退出，核对筛选、位置和焦点。
2. 新建输入 0、负数、三位小数，检查错误，再合法提交。
3. 回列表搜索新申请，核对状态。
4. 切主管甲打开新申请详情，再点“审批申请”进入第二层。填写说明后点“查看申请记录”打开第三层；用关闭、Esc 或遮罩逐层返回，确认审批说明仍在。审批成功退回详情并更新状态，再由员工甲查询结果。
5. 打开另一待审申请的审批抽屉，先验证空驳回原因被阻止，再填写完成。
6. 主管查看自己申请，确认不可自审批。
7. 在列表切换“模拟失败”，再打开抽屉提交或审批，确认失败提示留在抽屉且输入和数据未改变。关闭后切回正常场景再试。
8. 搜索不存在内容看空态，重置后重跑。
9. 以 1440px 和 375px 视口核对三层展示、键盘焦点与独立滚动；规范页从“打开详情抽屉”进入三层示例。

针对层叠逻辑运行 `node --test ai/scripts/test_drawer.cjs`；规范版本同步运行 `python3 ai/scripts/sync_design.py --check`。脚本检查不能代替实际页面渲染和正式组件验证。
