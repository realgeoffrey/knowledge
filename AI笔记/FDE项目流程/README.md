# 一人公司 FDE 项目流程

你负责需求、开发、测试与交付，客户确认业务。

## 日常入口

1. **扫一眼项目状态。** 看当前进展、实际阻塞和下一步。[项目状态](项目状态.md)
2. **处理待拍板事项。** 把短期或长期已有方向、仍须决定是否纳入需求的内容记在一起。由你决定是否写进《软件需求规格说明》。[待定&待确认](待定&待确认.md)
3. **核对并维护需求。** 每个需求阶段都对照两条依据。

   - **[《软件需求规格说明》](sources/软件需求规格说明.md)。** 由人维护，用业务人员能读懂的语言说明系统的目标、范围、流程和规则。
   - **[客户原始需求](sources/客户原始需求/) + [历次会议记录](sources/会议记录/)。** 从客户最初提出的需求出发，沿历次会议确认的补充和修订，还原当前适用的需求及其来由。

对照发现差异时，由人确认适用口径并把确认后的变动写入规格说明。

## 启动与日常

1. 将本模板复制到目标仓库根。已有工程按现行约定合并，保留代码和历史记录。
2. 由人按[资料放置与命名](sources/README.md#资料放置与命名)使用预建的来源目录，并维护现行规格。已有项目沿用实际位置时，把上面的链接指到对应资料。

## 八步流程

设计准备 → 项目启动 → 需求确认 G1 → 原型确认 G2 → 开发准备 G3 → 开发 G4 → 客户验收 G5 → 资料移交。

G1、G2、G5 由客户确认，G3、G4 由你核对执行证据。G1 与 G2 可同场分别记录。各阶段条件和固定版本见[验收记录](ai/records/acceptance.md)。
