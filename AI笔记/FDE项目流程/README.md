# 一人公司 FDE 项目流程

你负责需求、开发、测试与交付，AI 协助执行和维护记录；客户确认业务。这里是启动模板，不含应用源码，示例和占位不代表真实项目已完成或已获批准。

## 日常只看这两份

- [项目状态](项目状态.md)：本轮结果、未完成事项和下一步。
- [待澄清问题](待澄清问题.md)：回答客户问题、技术取舍及需要明确确认的事项。AI 提供背景、选项和材料，你填写回答即可；不确定就写待定。

AI 保存答复并回写内部记录后移除已处理问题。需要评审页面或证据时，会在问题旁给出直接入口。

## 启动与日常

1. 复制本目录到目标仓库根；已有工程合并使用，保留原规则、代码和记录。框架、验证和上线优先沿用现有工程；新后台可参考 RuoYi-Vue-Pro。
2. 给 Agent 真实目标、允许使用的资料和完成条件。用 Codex 在目标目录开新会话以加载 [项目规则](AGENTS.md)；其他客户端先确认是否自动加载，不能加载时按任务提供入口与必要片段。纯对话没有仓库工具时，只做分析或给出待执行步骤。
3. 明确的小改直接做针对性验证；续做、跨会话或范围不清时读 [项目状态](项目状态.md)。首次确认范围、改变已确认承诺、切换基线或交付时，走对应的确认流程。

日常可以直接说：“整理这份访谈，本轮不开发”“继续下一项已授权工作”“按有效需求只读复核实现”。

## 八步流程

| 步骤 | 要得到什么 |
| --- | --- |
| 设计准备 | 可讨论的设计草稿 |
| 项目启动 | 目标、范围、业务确认人与依赖 |
| 需求确认 G1 | 客户确认可验收的需求 |
| 原型确认 G2 | 涉及页面或已约定原型评审时，客户确认需求与业务页面的固定组合 |
| 开发准备 G3 | 工程、技术方案和基础验证链可运行 |
| 逐步开发 G4 | 有效验收条件有实现与验证证据 |
| 客户验收 G5 | 客户签认最终范围与版本 |
| 资料移交 | 交付资料齐全，记录实际去向与接收或转入证据 |

这是项目里程碑。G1/G2/G5 由客户确认，G3/G4 由你核对证据；G1/G2 可同场分别记录。无页面影响且无原型评审承诺的范围，由客户确认人按约定记 G2 不适用，不能用来改写已适用的门槛或已确认 AC。正式条件见 [验收记录](ai/records/acceptance.md)；任务完成不等于项目已验收或移交。

## 文档目录

日常入口在根目录。项目资料集中在 `ai/`，由 AI 按任务读取和维护。笔记、演讲稿等人用资料放在 `human/`。

| 位置 | 内容 |
| --- | --- |
| [human](human/) | 人用资料。检索排除写在 [.ignore](.ignore)，不能限制工具权限；敏感资料放在 Agent 无权访问的位置 |
| [specs](ai/specs/) | 项目概况、需求、方案、设计规范 |
| [records](ai/records/) | 问题澄清、验证追踪、批准与验收证据 |
| [handbook](ai/handbook/) | 需求、开发、长期维护与参考手册 |
| [tasks](ai/tasks/) / [changes](ai/changes/) | 当前任务与变更 |
| [meetings](ai/meetings/) / [materials](ai/materials/) | 访谈会议与客户原件 |
| [prototypes](ai/prototypes/README.md) | 可离线评审的设计展示与业务页面 |
| [scripts](ai/scripts/) | 结构检查、设计同步及测试 |

`AGENTS.md` 留在根目录，作为 AI 的统一入口；内部文件以用途命名，流程顺序由上表表达。完整事实只存一处，摘要只链接。

编号用于跨文档定位，日期用于区分真实事件。保留已有命名和原件来源，详见 [命名与日期约定](ai/handbook/maintenance.md#日期与迭代顺序)。
