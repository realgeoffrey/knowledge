# 业务规格

这里是唯一现行业务定义，供客户及项目成员评审，并约束后续实现。此目录应能单独交付和阅读，不依赖仓库其他文件。以下文件是填写骨架，不代表真实需求或确认。

## 阅读入口

[业务总览](00-overview/README.md) → [端到端流程](01-workflows/README.md) → [模块功能](02-modules/README.md)。按需要查[对象状态](03-states/README.md)、[共享规则](04-rules/README.md)、[实体关系](05-data/entities.md)、[数据字典](05-data/dictionary.md)和[验收场景](06-acceptance/README.md)。实际项目在这里维护按模块、按场景两套索引，均链接同一份定义。

## 唯一定义与维护

规格正文只描述业务范围、规则、异常和验收预期，不写提示词、内部执行步骤或实现方工作安排。维护命令与技术补充放在仓库内部说明。规格内引用使用本目录的相对路径和固定锚点，远程链接仅限经核实的法律法规官方发布页面。其他文件可以引用本规格，但本规格不能依赖目录外内容。

| 内容 | 放置位置 |
| --- | --- |
| 目标、范围、参与者、术语、非功能目标 | 总览 |
| 跨模块顺序、交接与正常/异常出口 | 工作流 |
| 功能前提、输入输出、专属规则 | 模块 |
| 对象状态、事件、条件、转换及联动结果 | 状态 |
| 跨模块权限、数量金额、单据及一致性约束 | 共享规则 |
| 业务对象关系、关键字段含义和口径 | 数据 |
| 给定条件、操作、可观察结果 | 验收 |

同一规则只定义一次，其他章节用相对链接和固定锚点引用。已有需求保留稳定 REQ/AC 编号；模板中的占位编号和示意图不算真实条目。不要每期复制整套文档；仅实际需要时按模块或场景拆成命名明确的 Markdown。

需由人确认的业务规则包括系统范围、参与角色及数据范围、审批、数量与金额、库存及其他实物、质量放行、状态转换、履约、对账结算、关键异常和责任边界。每项已确认规则在所属章节定义一次，并通过场景写明条件、操作和可观察结果；实现、原型、附件和示例不得隐式改变规则。可逆的内部命名、页面排序和技术实现由执行方在业务约束内决定，内部补充不作为业务规则来源。

原始资料仅在用户要求导入或核对指定内容时查阅；明确结论更新到唯一所属章节，不复制会议正文或维护过程台账。原型不能反过来缩减业务范围或把演示选择变成业务决定。
